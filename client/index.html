このアプリがしていること

Jev（TypeSafe の System One モデル）は文章を生成せず、noul（Yes/No の確率）・score（順序付き評価）・choice（選択肢の分類）の 3種類の質問に、確率付きの構造化された答えだけを返します。

1つの単語につき Jev に 1回だけ リクエストし、同じ state（単語）に対して次の質問を並列に投げています。

質問名種類見ていること
choicechoiceA と B のどちらをイメージするか（本命の判定）
choice_swappedchoice選択肢を B, A の順に並べ替えても答えが変わらないか（位置バイアス）
noul_a / noul_bnoul「A をイメージさせる」「B をイメージさせる」を別々に聞いたときの確率。両方高い・両方低いケースも見える
scalescore「明らかに A」〜「明らかに B」の5段階でどこに位置するか

各質問の結果を「A 寄り度合い（0〜1）」に揃えて平均したものを総合判定にしています。 質問ごとの判定が食い違う場合は「ゆらぎあり」と表示されるので、Jev が迷っている単語を見つけられます。

観察のヒント

  • 「並び順入替」の差（位置バイアス）が大きい単語は、Jev にとって判断が難しい単語です。
  • noul は A と B を独立に聞くので、「どちらもイメージしない」単語は両方とも低くなります。choice は必ずどちらかに振り分けるので差が出ます。
  • 「前提」を変えると判定がどう動くかを試してみてください（例: 南半球の人の感覚で）。
  • 補足説明を付けると、ラベルの解釈が固定されて判定が安定することがあります。

デモモード（API キー未設定時）はハッシュ値から作った疑似的な値を返します。Jev の本当の判定ではありません。
